# Anker Prime Dashboard — автономный сайт в Docker

[English documentation](README.md) · [Лицензия](LICENSE) · [Сторонние компоненты](THIRD_PARTY.md)

Сайт для **Anker Prime A2345, настольной зарядки 250 Вт**. Самостоятельно подключается к облаку Anker через HTTPS и MQTT/TLS. **Homey, Synology и телефон в качестве посредника не нужны.** Нужны интернет и существующий аккаунт Anker.

Внешний порт по умолчанию **80**: открывайте http://IP_СЕРВЕРА/. Внутри контейнера приложение слушает **8080**. Внешний порт выбирается при установке. Образ собирается из исходников; опубликованного Docker Hub образа нет. Интерфейс на русском языке, документация — на русском и английском. Проект неофициальный.

## Назначение и возможности

В браузере телефона/компьютера можно видеть работу портов, управлять зарядкой и изучать историю. Сервер собирает данные при закрытом браузере. Счётчики каждого экземпляра самостоятельные.

| Возможность | Описание |
| --- | --- |
| Измерения | Мощность, напряжение и ток шести портов C1–C4/A1–A2, суммарная мощность и свежесть данных. |
| Выключатели | Четыре группы USB-C и общая группа USB-A. A1/A2 имеют отдельные измерения/графики, но общий выключатель, лимит и счётчик после сброса. |
| Режимы | AI Power, приоритет подключения, два ноутбука, малая мощность и пользовательский режим. Пользовательские лимиты отображаются как лимиты только в пользовательском режиме. |
| Лимиты | USB-C с шагом 5 Вт, USB-A 0/15/24 Вт; предпросмотр и автоматическое уменьшение других USB-C лимитов в пределах 250 Вт. |
| Энергия | Отданная энергия после сброса, дата сброса и сброс с подтверждением. |
| Таймеры | Поддерживаемые таймеры портов/групп и расписания зарядки. |
| Дисплей | Яркость, время отключения, девять известных скринсейверов. |
| Часы/управление | Настройки часов, праздничное оформление, расписание часов, направление энкодера и приоритет портов. |
| Названия | Собственные названия портов/групп, сохранённые на сервере. |
| История | Отдельные графики Вт/В/А шести портов за 1/6/24 часа и 7/30 дней; пик мощности, оценка энергии, время зарядки и полнота данных. |
| Аккаунт | Запрос почты, пароля, региона и страны при первом запуске; восстановление после перезапуска и смена аккаунта. |

Лимит — настройка распределения бюджета. Реальное напряжение и мощность определяются USB-PD и подключённым устройством. Принудительного фиксированного напряжения нет. Точность физического ограничения требует дальнейших испытаний электронной нагрузкой; шаг интерфейса 5 Вт не означает доказанную точность аппаратного ограничения.

Запись примерно каждые 10 секунд, хранение 30 дней. Энергия оценивается по измеренной выходной мощности; большие пропуски не экстраполируются. Это выходная энергия, а не потребление из розетки. История Anker, Homey Insights и прежнего сайта Synology не импортируется. Сбор начинается после входа.

## Что необходимо

- A2345 уже добавлена в официальный Anker на телефоне, подключена к Wi-Fi и онлайн.
- Почта/пароль аккаунта, регион EU/Global и двухбуквенная страна регистрации.
- Сервер Docker с интернетом, стабильным адресом в домашней сети и местом для образа/истории.
- Docker Engine и плагин Compose. Проверено на Ubuntu 24.04 x86_64; другие платформы проектом не проверены.
- Свободный порт: по умолчанию **80**. Отдельно устанавливать Node.js на сервер не нужно.

## Установка с нуля на Ubuntu

### 1. Подключитесь к серверу

Откройте Terminal на macOS/Linux или PowerShell на Windows:

~~~bash
ssh ИМЯ_ПОЛЬЗОВАТЕЛЯ@IP_СЕРВЕРА
~~~

Замените имя и IP своими. Введите пароль Ubuntu; символы при вводе не отображаются. Дальнейшие команды выполняются на сервере. sudo может повторно спросить пароль Ubuntu. Пароль Anker не вводится в терминале и не записывается в .env.

### 2. Установите Docker, если его ещё нет

Проверьте sudo docker --version и sudo docker compose version. Если обе команды работают, пропустите шаг. Для чистой Ubuntu используется официальный подписанный APT-репозиторий. Если установлен конфликтующий Docker, сначала прочитайте [официальную инструкцию](https://docs.docker.com/engine/install/ubuntu/), не удаляйте пакеты вслепую.

~~~bash
sudo apt update
sudo apt install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world
sudo docker compose version
~~~

### 3. Скачайте проект

~~~bash
sudo apt install -y git
git clone https://github.com/edsallo/anker-prime-dashboard.git
cd anker-prime-dashboard
cp .env.example .env
nano .env
~~~

Для публичного репозитория аккаунт GitHub не требуется. git clone скачивает исходники. nano открывает редактор. После изменений нажмите Ctrl+O, Enter для сохранения, Ctrl+X для выхода.

### 4. Укажите адрес сервера

Пример файла .env:

~~~dotenv
SERVER_IP=192.168.1.100
WEB_PORT=80
PUBLIC_URL=http://192.168.1.100
~~~

Замените оба IP на адрес вашего сервера. SERVER_IP должен принадлежать этому серверу: порт публикуется только на этом адресе. PUBLIC_URL — точный адрес браузера, без завершающего /. Для порта 80 не пишите :80. Настройка используется проверкой Host/Origin.

.env исключён из Git и сборки Docker. В нём только настройки установки, не пароль Anker. WEB_PORT по умолчанию 80; SERVER_IP и PUBLIC_URL обязательны, чтобы публичный проект не использовал частный адрес автора.

### 5. Создайте хранилище и запустите

~~~bash
sudo mkdir -p data
sudo chown 1000:1000 data
sudo chmod 700 data
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
~~~

Контейнер работает под UID/GID 1000. Поэтому data/ должен принадлежать 1000:1000, даже если ваш пользователь Ubuntu имеет другой UID. Первая сборка скачивает Node.js и зависимости и может занять несколько минут. Up (healthy) означает работу веб-сервера, а не подключение аккаунта Anker.

### 6. Первый вход

Откройте http://192.168.1.100/ в той же сети, заменив IP своим. Первый запуск перенаправляет на /setup.

1. Введите почту и пароль аккаунта Anker с телефона.
2. Выберите EU/Global и страну регистрации, например DE/RU/US. По умолчанию в форме DE; при необходимости измените.
3. Нажмите «Подключить зарядку».
4. После успешного входа и подключения MQTT поддерживаемые A2345 обнаружатся автоматически.

Аккаунт сохраняется зашифрованным и восстанавливается после перезапуска. Для смены используйте «Аккаунт». Пароль не подставляется в форму. Неудачная смена сохраняет прежнее подключение. Дополнительные этапы MFA/CAPTCHA не реализованы и не обходятся; такой аккаунт может не подключиться.

## Другой порт

Например 8085:

~~~dotenv
SERVER_IP=192.168.1.100
WEB_PORT=8085
PUBLIC_URL=http://192.168.1.100:8085
~~~

Примените sudo docker compose up -d и откройте http://192.168.1.100:8085/. Внутренний порт остаётся 8080. Несколько точных разрешённых адресов можно перечислить в PUBLIC_URL через запятую; DNS и сертификаты это не создаёт. Один каталог данных должен использовать только один экземпляр.

## Запуск через docker run

Из каталога скачанного проекта, после создания data/ с правами выше:

~~~bash
sudo docker build -t anker-prime-dashboard .
sudo docker run -d --name anker-prime-dashboard \
  --restart unless-stopped --init --user 1000:1000 \
  --read-only --tmpfs /tmp:size=16m,mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  -p 192.168.1.100:80:8080 \
  -e SITE_ORIGINS=http://192.168.1.100 \
  -e DATA_DIR=/data -e TZ=Europe/Moscow \
  -v "$PWD/data:/data" anker-prime-dashboard
~~~

Замените IP в двух местах. Выберите Compose или docker run; не запускайте оба с одним хранилищем. Для этого способа журнал — sudo docker logs anker-prime-dashboard, перезапуск — sudo docker restart anker-prime-dashboard.

## Эксплуатация и обновление

Для Compose команды выполняются из каталога проекта:

~~~bash
sudo docker compose ps
sudo docker compose logs --tail=100 anker
sudo docker compose restart anker
sudo docker compose stop
sudo docker compose start
~~~

restart: unless-stopped обеспечивает запуск после сбоя и запуска Docker/сервера, кроме явно остановленного пользователем контейнера. Docker должен быть включён в автозапуск. Обновление:

~~~bash
git pull --ff-only
sudo docker compose up -d --build
~~~

Сохраняйте .env и data/. При сообщении Git о локальных изменениях сначала изучите их; не удаляйте настройки и данные ради обновления.

## Резервное копирование и восстановление

Остановите контейнер, скопируйте весь data/, запустите обратно. Пример закрытой копии вне репозитория:

~~~bash
sudo docker compose stop
sudo sh -c 'umask 077; tar -czf /root/anker-prime-data-backup.tgz data'
sudo docker compose start
~~~

Для восстановления остановите новый экземпляр, восстановите data/ с прежней структурой, назначьте владельца 1000:1000 и права каталога 700, запустите. Ключ и зашифрованный аккаунт восстанавливаются вместе. Резервные копии не публикуйте в GitHub.

| Хранилище | Назначение |
| --- | --- |
| data/vault.key | Секретный локальный ключ шифрования. |
| data/account.enc | Аккаунт/сессия, зашифрованные AES-256-GCM. |
| data/devices-state.json | Названия и состояние энергии после сброса. |
| data/history/ | Измерения и каталог графиков. |
| .env | Адрес сервера, порт и разрешённые адреса браузера. |

Пересоздание контейнера не удаляет bind-mounted data/. Аккаунт исключён из образа, файлы имеют закрытые права. Пароли/токены намеренно не журналируются. Ключ хранится рядом с шифротекстом: это не защита от полного доступа к серверу/копии. HTTPS и MQTT/TLS проверяют сертификаты облака.

## Модель доступа

После настройки аккаунта у сайта **нет отдельной авторизации посетителей**: любой с доступом к разрешённому адресу может видеть зарядку и управлять ей. Host/Origin — не парольная защита. По умолчанию доступ из браузера по HTTP.

Используйте доверенную домашнюю сеть, не пробрасывайте порт напрямую в интернет. Для удалённого доступа нужен отдельный HTTPS-прокси с авторизацией и соответствующий PUBLIC_URL. Опубликованные порты Docker могут обходить UFW; учитывайте документацию Docker при ограничении доступа.

## Решение проблем

| Проблема | Что проверить |
| --- | --- |
| Port already allocated | Порт занят. Измените WEB_PORT и PUBLIC_URL, примените Compose. |
| Cannot assign requested address | SERVER_IP не принадлежит серверу. Проверьте hostname -I. |
| Unknown host / Origin denied | Адрес браузера отличается от PUBLIC_URL: IP/имя/протокол/нестандартный порт. |
| Unable to initialize Anker service | Права/владелец data/ и место на диске. Не удаляйте vault.key для исправления прав. |
| Docker permission denied | Используйте sudo, как в инструкции. |
| Compose отсутствует | Установите docker-compose-plugin; нужна docker compose, не docker-compose. |
| Зарядка не найдена | Регион, страна, аккаунт, модель A2345 и онлайн-статус в Anker. |
| Ошибка входа | Пароль/регион; после частых попыток подождите минимум минуту. |
| Устаревшие данные | Интернет сервера и Wi-Fi зарядки; сервер автоматически повторяет подключение. |
| Пустые графики | Новому экземпляру нужно время после подключения для накопления истории. |
| Счётчики отличаются от Homey/Synology | Каждый экземпляр имеет самостоятельные данные. |

Для сообщения об ошибке укажите модель, шаги воспроизведения, статус Docker и очищенную ошибку. Не прикладывайте файлы аккаунта, ключи, облачные ответы и резервные копии.

## Разработка и проверка

server.js — HTTP/UI; service.js — аккаунт, соединения, энергия; lib/ — облако, MQTT, протокол, лимиты и шифрование; history.js — история; public/ — интерфейс; test/ — тесты.

Для разработки с Node.js 22+:

~~~bash
npm ci
npm test
~~~

Тесты проверяют протокол, подтверждения команд, обновление сессии, шифрование/восстановление аккаунта, энергию при пропусках, историю и защиту HTTP. Установка/перезапуск проверены на Ubuntu 24.04 с Docker. Реальное соединение требует успешного входа пользователя. Все варианты ограничения мощности под электронной нагрузкой ещё не проверены.

## Ограничения и лицензия

Обнаруживается только A2345. Облачный API/прошивка недокументированы и могут измениться. Интернет обязателен: это не офлайн-API локальной сети. Оформление дисплея зависит от прошивки/облака. Homey Flow/Insights/виджеты в этот сайт не входят. Измерения потребления из розетки и фиксации напряжения нет.
